# Security and safety reporting

SeaRisk UA is a research prototype. Do not submit questionnaire values, health information, names, contact details, employer records, incident narratives about identifiable people, credentials, or exploit details in a normal GitHub issue.

The current application is static and has no accounts, cookies, analytics, runtime secrets, or questionnaire backend. Changes involving cloud storage, authentication, telemetry, third-party AI/APIs, incident uploads, or individual decisions require the review in `docs/governance/privacy-and-misuse-review.md`.

## Software vulnerability

Report a suspected vulnerability through the repository's private GitHub Security Advisory channel when it is available to you. If you only have access through the restricted pilot, use the monitored pilot-coordinator contact named in the invitation and mark the message **Security — SeaRisk UA**.

Include the affected version, reproducible steps, impact, and a safe contact method. Use synthetic data only. Maintainers should acknowledge the report within two working days, assess severity, preserve evidence, and avoid publishing details until a mitigation is available.

## Privacy, misuse, or safety incident

Stop the affected pilot activity and contact the pilot coordinator through the monitored channel named in the invitation. Examples include unexpected transmission or retention of questionnaire values, an employer requesting individual results, use for work allocation or discipline, exposure of an identifiable incident record, or a misleading safety claim.

The coordinator follows `docs/governance/incident-response.md`. GitHub may contain only a sanitised tracking issue with no personal or health data.

## Immediate danger

This repository is not an emergency or navigational reporting channel. For immediate danger, a shipboard emergency, or an occupational incident, use the vessel, employer, and competent-authority procedures that already apply.
